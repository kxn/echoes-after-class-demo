# 帧节奏与垂直步频修订

2026-09-15，Godot 4.7.2 Compatibility，AMD RX 5700 XT，最大化窗口 3840×1984。同一场景预热 2 秒，采样随后 5 秒，用 `Time.get_ticks_usec()` 测量真实帧间隔。

| 模式 | 平均帧间隔 | P95 | P99 |
| --- | ---: | ---: | ---: |
| 垂直同步，不另限帧 | 24.43 ms | 32.25 ms | 32.64 ms |
| 垂直同步 + 60 帧上限 | 26.35 ms | 32.03 ms | 32.69 ms |
| 关闭垂直同步，仅 60 帧上限 | 16.67 ms | 16.72 ms | 16.74 ms |
| 关闭垂直同步，不限帧 | 1.97 ms | 1.98 ms | 7.34 ms |

据此，当前入口关闭窗口垂直同步，由 `Engine.max_fps=60` 控制帧率。此结果定位到本机窗口呈现等待，不把问题归咎于绘画贴图或直接降低光影质量。未确认驱动/桌面合成器内部原因；其他显示环境可能不同。

另停用已隐藏的旧 2D 角色动画更新；桌面柔影在人物投影范围外直接退出，避免执行九次无效纹理采样。未降低阴影分辨率、关闭动态阴影或删除法线。

垂直步频原先使用 3D 代理长度：120 个逻辑像素换排，深度被拉伸至 3.5 单位，另含 1.2 单位高度分量，动画约被放大 3.08 倍。现在步长使用 `(dx, dz * 120 / 350)`，还原逻辑移动尺度；同样的逻辑距离，横竖推进同样多动画帧。手动换排速度仍是横走的 0.7 倍，脚步声继续由同一落脚事件触发。

新增横竖等距步频与所有对话入口的回归检查，当前共 532 项通过。初步 `baseline.json` 使用引擎 delta 而非墙钟，不能与后面的墙钟报告直接计算优化百分比。

复测：Godot `--path . --script tools/perf_probe.gd -- --label=cap-only --cap-only`；比较模式为 `--vsync-only`。测试不依赖固定帧率影片的录制速度。
